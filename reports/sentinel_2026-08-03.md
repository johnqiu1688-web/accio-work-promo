## ⚠️ Step 4 · 附带发现：本机 DNS 被劫持

上线复测时四个页面均返回**阿里系「域名拦截」页**（1,461 字节，含 aplus 埋点），一度误判为发布失败。排查结论：

| 检查项 | 结果 |
|---|---|
| GitHub Pages 构建 | ✅ `eab184f` built，无错误 |
| 本机 DNS 解析 getquon.com | ❌ `59.82.113.122`（非 GitHub） |
| 阿里公共 DNS 223.5.5.5 | ✅ `185.199.108-111.153` |
| Cloudflare 1.1.1.1 | ✅ `185.199.108-111.153` |
| 直连 185.199.108.153 | ✅ 全部 200，新内容命中 |

**判定**：站点本身完全正常，是本机所在网络环境（运营商 / 网关 DNS）把 getquon.com 解析到了拦截页。外部用户不受影响。

**影响**：Sentinel 巡航如果继续用本机 DNS，健康检查结果不可信 —— 会把正常站点误报为故障，或反过来漏掉真故障。

**处置建议**：
1. 本机 DNS 改为 `223.5.5.5` / `1.1.1.1`
2. Sentinel 巡航脚本固定加 `--resolve getquon.com:443:185.199.108.153`，绕开本地解析
3. 顺带核查该域名是否被误列入某拦截名单（GitHub Pages 自定义域被误伤的常见情形）
