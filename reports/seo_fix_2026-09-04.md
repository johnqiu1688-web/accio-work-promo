## 一、修了什么

### 1.1 补齐 canonical（15 个页面）

**问题**：60 个 HTML 页中有 16 页缺 `rel="canonical"`，**包括根路径首页 index.html**。

缺失 canonical 会让搜索引擎自行判断「哪个 URL 是正版」。站点存在 `/`、`/index.html`、`/index_cn.html`、`/index_en.html` 多个近似入口，缺 canonical 时容易被判为重复内容并分散权重。

**已补页面**：

| 页面 | canonical 指向 |
|---|---|
| index.html | `https://getquon.com/`（根路径，非文件名） |
| index_en.html | 自身 |
| daily_digest.html / daily_digest_en.html | 自身 |
| install_tutorial.html | 自身 |
| troubleshooting.html | 自身 |
| opc_strategy.html | 自身 |
| security_deepdive.html | 自身 |
| shopify_automation.html / shopify_workflow.html | 自身 |
| skill_1688_audit.html / skill_icbu_sniper.html / skill_okki_revival.html | 自身 |
| sourcing_hacks.html | 自身 |
| yiwu_sourcing.html | 自身 |

**覆盖率**：16/60 缺失 → **59/60 覆盖**。

唯一未补的是 `baidu_verify_codeva-T0rPR5vXAf.html`（百度站长验证文件，本就不应被索引，**有意保留**）。

**校验**：canonical 值重复项 **0** —— 无两页互抢同一 canonical。

---

### 1.2 补齐 hreflang 互指（3 组中英对照页）

**问题**：站点有中英双版内容，但**全站无一处 hreflang**。

对 Google 而言，缺 hreflang 的中英双版极易被判为重复内容，只保留一个版本参与排名 —— 另一个的权重被吞掉。这是双语站的典型排名抑制原因。

**已建立互指的三组**：

| 英文页 | 中文页 |
|---|---|
| `/`（index.html） | `/index_cn.html` |
| `/anti-ban-safety.html` | `/q/anti-ban-safety.html` |
| `/skills.html` | `/q/skills.html` |

每页均加 3 个标签：`hreflang="en"`、`hreflang="zh-Hans"`、`hreflang="x-default"`（指向英文版）。

**校验**：六个页面 hreflang 标签数均为 3，双向对齐。

---

### 1.3 清理 index.html 重复文档块

**问题**：`index.html` 在第 412 行已 `</body></html>` 闭合，其后又追加了**一整段完全相同的脚本 + 第二组闭合标签**（413–430 行）。

`</html>` 之后的内容属无效 HTML。浏览器容错可正常渲染，但爬虫可能在首个 `</html>` 处停止解析。作为根路径首页，这个问题影响面最大。

**处理**：删除 413–430 行（18 行），已确认被删段为**纯重复脚本**（同样的 placeholders 轮播逻辑，原文件中 `placeholders` 出现 2 次，现为 2 次 → 保留 1 份完整逻辑）。

**结果**：`</html>` 从 2 个降为 1 个，行数 431 → 413。

## 二、一次失误及其处理（必须记录）

### 2.1 发生了什么

`index_cn.html` 同样有 2 个 `</html>`。我**假定它与 index.html 情况相同**，用同一套逻辑删除了尾部区块。

**这是错的。** 校验脚本的输出已给出警告 —— 被删段「含重复脚本: **False**」，与 index.html 的 `True` 不同。

`git diff` 显示实际删掉的是**功能代码**：

```
- var hotIds=['m144','credits','okki','1688','icbu-reply',...];
- var el=document.getElementById('hot-grid'); ...
- el.innerHTML=hotIds.map(...)
```

这是首页「热门问题」网格的渲染逻辑，**不是重复块**。若发布，中文首页的热门问题模块会直接空掉。

### 2.2 如何发现和处理

1. 校验脚本输出 `含重复脚本: False` → 立即停止，未继续提交
2. `git diff` 确认删除内容性质
3. `git checkout index_cn.html` 立即回滚
4. 回滚后 hreflang 一并被撤 → 重新单独插入，**只改 head，不动文档结构**
5. 复核 `hotIds` 出现 4 次、行数 1062，功能完整恢复

**index_cn.html 最终保留 2 个 `</html>`** —— 既有结构中夹带功能代码，改动风险大于收益，本次不予处理。

### 2.3 教训

**同类症状不等于同类病因。** 两个文件表面都是「2 个 `</html>`」，实际一个是冗余、一个是结构缺陷夹带功能代码。批量处理前必须逐个验证被改内容的性质，而不是靠模式匹配推断。

本次是校验环节抓住了它。若当初只检查「`</html>` 数量是否降为 1」而不检查被删内容，这个 bug 会直接上线。

## 四、关于效果的诚实说明

**这些修复不保证流量上涨。**

canonical 和 hreflang 属于「消除抑制因素」，不是「增加曝光」。它们解决的是**权重分散和重复内容判定**，而 Google 零出量的根因尚未确诊 —— 可能还包括排名位置过低、站点权重不足等本次无法排查的因素。

**要确诊仍需 Google Search Console**，而它需要你验证。在此之前，我只能修掉已知的技术缺陷。

**生效周期**：搜索引擎需重新抓取才会应用新的 canonical / hreflang，通常数天到数周。**不会立刻见效。**

## 五、诊断过程中被推翻的三个假设

记录下来，避免后续重复走弯路：

| 假设 | 实测 | 结论 |
|---|---|---|
| 低流量页 title 不是查询式 | skill-radar 的 title **已经是**「Skill 怎么选?」查询式 | ❌ 推翻 |
| 低流量页内链不足 | skills_lab 被 **45 页**链接、skill-radar 被 **29 页**链接，远高于 guide.html 的 **5 页** | ❌ 推翻，且完全相反 |
| 低流量页缺结构化数据 | skill-radar、anti-ban 均有 `FAQPage` + 3 个 `Question`，比 guide.html（0 个）更完整 | ❌ 推翻 |

**这三项都不是差异点。** 内链和结构化数据甚至优于高流量页。

这意味着 §2 增长方案中「把观点页改造成问答页」的建议，**依据不如原先判断的那样充分** —— 真实差异更可能在搜索需求本身（有多少人搜这个问题），而非页面技术属性。后续不应盲目改造，需先有关键词数据支撑。
