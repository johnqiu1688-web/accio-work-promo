团队空间会自己长 Skill 了 —— 那还怎么选?

v0.27.0 · 2026-07-29

Accio Work v0.27.0 起,团队空间的「自动提炼 Skill」默认开启:协作过程里跑顺的流程会被自动沉淀成可复用 Skill。这是好事,但也带来一个新问题 —— 三个月后你的 Skill 列表里会混着「官方榜单装的」和「团队自己长出来的」,数量翻几倍,选型反而更难。给几条实操建议:

自动提炼的 Skill 是「你团队的」,不是「通用最优的」

它沉淀的是你们已有的做法。如果原本流程就次优,提炼出来的也是次优的固化版。榜单 Skill 的作用是提供外部参照系 —— 拿 Top 20 的成熟做法对照自己提炼出的版本,才知道差在哪。

先装配单,再开自动提炼,别反过来

新团队建议先按上面的 3 / 5 件套把基础动作跑顺 2-4 周,再让自动提炼去沉淀。空白团队一上来就自动提炼,只会把摸索期的混乱流程存下来。

每月清一次,重复能力只留一个

自动提炼最常见的副作用是同一件事有三四个近似 Skill。建议每月固定清理:同一能力域只保留一个主用版本,其余归档。判断标准用调用次数,不用创建时间。

多店团队:确认提炼出的 Skill 里没夹带店铺数据

自动提炼来自真实协作过程,可能把具体客户名、店铺 ID 写进 Skill 描述。跨店复用前先过一遍,把标识性信息换成变量。详见 Anti-Ban 2.3 合规底线。

另:v0.27.0 同期完成了 Shopify 专家 Agent 迁移,如果你在做 1688→Shopify 链路,可参考我们的 三步上架 SOP。

知识库上线后,一半的「Skill 需求」其实不该装 Skill

v0.28.1 → v0.32.0 最新

v0.28.1 上线了个人知识库与团队知识库,v0.30.0 补上文件上传同步与本地预览,v0.31.0(2026-08-26)又让团队空间内也能建个人知识库。这件事对选型的影响比它看起来大 —— 因为在此之前,很多团队是拿 Skill 当资料库用的:把报价单、话术模板、品类参数硬塞进 Skill 描述里。现在这条路该改了。

v0.31.0 补了一块关键拼图。此前团队空间只有团队知识库,意味着你想放点「只有自己用的东西」——半成品话术、个人客户备注、还没验证的参数表——要么塞进团队库污染同事,要么塞回 Skill 描述。现在团队空间里可以建个人知识库,私有资料终于有了正规去处。

对多店卖家的实际意义:每家店的独有资料(客户名单、定价策略、供应商联系人)可以各自归位,不必再靠「都塞进一个 Skill」硬扛。这和我们一贯主张的按店隔离是同一个方向。

v0.32.0(2026-09-02)继续加码:团队体验版也支持个人知识库了,门槛进一步降低;同时个人空间的 Agent 支持一键复制到团队空间。这条对多店团队很实用 —— 自己先在个人空间把一个店调通,验证没问题再整体搬到团队,不用在团队里边试错边影响同事。

该做成 Skill 的:动作

有明确输入输出、可重复执行的流程。比如「抓后台最近 20 个品 → 套模板出主图 → 生成发品表」。判断标准:你能说清「跑一次它做了什么」。

该放知识库的:事实

会变、要查、不执行的内容。报价区间、认证清单、客户偏好、历史成交记录。判断标准:你只是想让 Agent「知道」,而不是「做」。

把资料塞进 Skill,维护成本会在三个月后爆发

Skill 描述里写死的报价、政策、参数,改一次就要动一次 Skill,还要重新验证它没被改坏。放知识库则是改文件即生效,不触碰执行逻辑。这是「动作」和「事实」必须分开的根本原因 —— 它们的变更频率差一个数量级。

重新审一遍你现有的 Skill 列表

如果某个 Skill 的主体是一大段固定文本(话术库、参数表、FAQ),它大概率是知识库的活。拆出来之后 Skill 会变薄,但触发准确率会上升 —— 描述越聚焦动作,匹配越准。这一条对已经开了自动提炼的团队尤其值得做。

多店团队:知识库的隔离要单独确认一次

团队知识库是共享的。把 A 店的客户名单、成交价传进去,B 店的协作任务同样能读到。这跟 Skill 夹带店铺数据是同一类风险,但更隐蔽 —— 因为上传文件时没人会觉得那是在「配置权限」。上传前先问一句:这份文件是否所有店都该看见?详见 Anti-Ban 2.3 合规底线。

一句话:Skill 装能力,知识库装上下文。这轮分家做完,再回头看 Top 20 的配单,你会发现要装的比原来更少。
