M144/M145 连接失败 / 端口握手

一句话结论

M144 是 Accio Work 桌面端与本地服务"握手失败"的报错。90% 的情况靠"把 Chrome 设为默认浏览器 + 彻底退出重启 App"就能解决；若反复掉线，是 Chrome 148+ 的 Service Worker 回收机制导致，需要保活方案根治。下面给可照做的完整步骤。

先自查：你是不是这个问题？

  • App 启动后一直转圈，提示"连接中 / M144 / M145"
  • 任务发不出去，或发出去没反应
  • 用一会儿就断，过几秒又自己连上、反复掉线
  • 换了网络、重装也没彻底好

命中任意一条，按下面步骤处理即可。

官方标准口径

连接类问题官方建议：确保 Chrome 为默认浏览器，完全退出 App 后重新启动以触发本地端口监听；检查桌面端 / Web 端数据同步状态，保持 Chrome 与 App 为最新版本。

来源：官方帮助中心·安装与更新

FDE 实战：分步解决（照着做）

1

把 Chrome 设为系统默认浏览器（解决 90%）

M144 本质是 App 连不上本地端口（127.0.0.1）。Accio Work 依赖默认浏览器拉起本地服务。
· Windows：设置 → 应用 → 默认应用 → 把"Web 浏览器"设为 Chrome
· macOS：系统设置 → 桌面与程序坞 → 默认网页浏览器 → 选 Chrome
设置后彻底退出 Accio Work（不是关窗口，要右键退出/任务管理器结束进程），再重新打开。

2

关闭 VPN / 全局代理后重试

全局代理会拦截本地 127.0.0.1 通信，导致握手失败。临时关闭 VPN / 系统代理，或将 127.0.0.1、localhost 加入代理白名单（不走代理），再重启 App。

3

确认 Chrome 与 App 均为最新版

旧版本扩展协议不匹配也会握手失败。Chrome 地址栏输入 chrome://settings/help 检查更新；App 内检查更新到最新版。

4

反复掉线？这是 Chrome 148+ 的根因

如果前 3 步能连上、但用一会儿又断、反复掉线，根因是 Chrome 148+ 的 Manifest V3 机制：扩展后台 Service Worker 在空闲约 5 秒后会被浏览器回收，导致本地通信链路中断。
· 临时缓解：保持 Accio Work 窗口在前台、不要长时间最小化或切到后台标签
· 根治：部署"持续心跳保活"方案，定时维持本地 127.0.0.1 链路活跃，使 Agent 在后台挂载也不掉线。

经验参考：步骤 1–3 可解决绝大多数 M144；仅"反复掉线"类需走步骤 4 的保活方案。（以上为基于官方文档与 Chrome 扩展机制的实战整理，非官方承诺指标）

怎么避免再次发生

  • 固定用 Chrome 作默认浏览器，不要频繁切换默认浏览器
  • Chrome 自动更新后，留意扩展是否需重新加载
  • 长时间跑任务时保持 App 前台，或启用保活方案
  • 代理软件设置里把 localhost / 127.0.0.1 加入直连白名单
